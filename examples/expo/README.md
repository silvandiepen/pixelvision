# pixelvision · Expo (React Native)

pixelvision in an Expo app, running on Hermes, React Native's JavaScript engine.

On start, the app scans a bundled sample photo; **Pick a photo** scans one from the photo library.
It runs `grayscale`, `gaussianBlur` and `canny` for an edge map and finds the document with
`findDocument`, then shows the photo with the document's outline drawn on top and the time
detection took. The corners are also shown as `"x,y x,y x,y x,y"` (top-left, top-right,
bottom-right, bottom-left) in a text with `testID="result-corners"`, and the time in
`testID="detect-time"`, so UI tests can read them.

## How pixels are read

React Native has no canvas, so the app decodes images itself:

1. `expo-image-manipulator` scales the photo down to at most 1280 px and saves it as a JPEG. This
   also turns HEIC and PNG photos into one format.
2. `expo-file-system` reads the JPEG's bytes.
3. [`jpeg-js`](https://github.com/jpeg-js/jpeg-js), a pure-JavaScript decoder with no dependencies,
   turns them into RGBA pixels.

Both Expo modules ship in Expo Go and in every Expo app, so the example adds no native code of its
own. The outline is drawn with plain views, so it needs no drawing library either. A GPU route
(`expo-gl` or Skia) would read pixels faster, but adds a large native module for a step that is
not the bottleneck.

## Files

- `src/App.tsx`: the screen: buttons, the photo with its outline, the time and the corners.
- `src/detect.ts`: the pixelvision part: edges and document corners.
- `src/pixels.ts`: reads and decodes a photo or the bundled sample.
- `src/Outline.tsx`: draws the document's outline over the photo.
- `src/detect.test.ts`: runs the detection on the sample in Jest (`jest-expo`).
- `assets/sample.jpg`: the sample, made by `scripts/make-sample.mjs` (the same scene the web
  starters are tested with).
- `metro.config.cjs`: Metro set up for the pnpm monorepo.

## Monorepo setup

`pixelvision` comes from `workspace:*` and is resolved through its `exports`, so the app uses the
built `dist`, like a package from npm. `metro.config.cjs` watches the repository root, looks up
packages in this app's `node_modules` and then the root's, and follows pnpm's symlinks. To use the
app outside the repository, replace `"pixelvision": "workspace:*"` with a version from npm and
remove `watchFolders` and `nodeModulesPaths` from the Metro config.

## Run

From the repository root:

```sh
pnpm install
pnpm --filter pixelvision build
```

In Expo Go, on a simulator or a phone (no native build):

```sh
pnpm --filter @pixelvision/example-expo start
```

As a development build on the iOS simulator (needs Xcode and CocoaPods, and several GB of disk for
the pods and the build). `ios/` and `android/` are generated by `expo prebuild` and not committed:

```sh
cd examples/expo
npx expo run:ios --device "iPhone 17 Pro Max"
```

## Test

```sh
pnpm --filter @pixelvision/example-expo test
```

The Jest test decodes the bundled sample with the app's decoder, runs the detection, and checks
the corners are within 4 px of where the sample's document is. It runs in `pnpm test` and CI. Jest
runs on Node with React Native's module setup, not in Hermes: the Hermes run of the same library
code is `packages/compat`, and the app itself on a simulator or device. The iOS build is not part
of CI.
